# Domain docs

## Layout

This repo uses one context:

- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

## Consumer rules

Before exploring the codebase, read the glossary and ADRs
relevant to the work.

If these documents do not exist, proceed silently.
Create them lazily through domain-modeling when terms
or decisions are resolved.

Use glossary terms in issue titles, proposals, hypotheses,
and test names. Reconsider unfamiliar terminology or note
a real vocabulary gap for domain-modeling.

If a proposal contradicts an ADR, identify the ADR and
explain why the decision should be reopened.
